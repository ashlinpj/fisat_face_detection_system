1. PROJECT PURPOSE AND SCOPE
================================================================================

1.1 Purpose
-----------
This project implements a complete face-based visit logging system designed for
college canteen monitoring. It identifies registered students in real time,
records visit events, and provides operational interfaces for admins.

1.2 Core Problems Solved
------------------------
- Verifies whether a student actually visited the canteen.
- Maintains timestamped evidence of visits.
- Reduces false complaint disputes using objective logs.
- Supports both local webcam and RTSP network stream input.

1.3 Main Capabilities
---------------------
- Real-time face detection.
- Face recognition against registered students.
- Student registration from live camera frames and image files.
- Visit log storage and filtering.
- Statistics dashboard and CSV export.
- CPU/GPU-aware runtime behavior.

6.2 RTSP Mode
-------------

- Applies RTSP buffer and transport options.
- Supports reconnect attempts and delay.

6.3 Low-latency Capture Strategy in CLI
---------------------------------------
- Dedicated capture thread reads frames continuously.
- Frame queue has bounded size (config.FRAME_BUFFER_SIZE).
- Old frames are dropped to keep only freshest data.
- Optional pre-grab calls skip stale packets on RTSP streams.

6.4 Recovery Behavior
---------------------
- CLI and GUI both attempt RTSP reconnection on repeated read failures.
- CLI supports optional periodic RTSP restart interval to clear artifacts.


================================================================================
7. DETECTION, RECOGNITION, LOGGING PIPELINE
================================================================================

7.1 High-level Pipeline
-----------------------
For each frame:
1. Detect faces (DNN primary, Cascade fallback).
2. Cache detections by frame hash for short TTL reuse.
3. Every Nth frame, crop+enhance face and queue recognition task.
4. Background recognition thread computes embedding and best match.
5. Main processor consumes latest result and overlays labels.
6. VisitService logs known matches with cooldown protection.

7.2 Detection Layer (app/services/detection_service.py)
-------------------------------------------------------
- Tries OpenCV DNN SSD detector first when USE_DNN_DETECTOR is enabled.
- Filters detections by confidence, minimum size, and aspect ratio.
- Converts detections to square boxes for consistent downstream crops.
- Falls back to Haar Cascade when DNN is unavailable or no result.

7.3 Recognition Layer (app/services/recognition_service.py)
-----------------------------------------------------------
- Uses DeepFace.represent() with enforce_detection=False and detector_backend=skip.
- Uses configurable embedding model from config.FACE_EMBEDDING_MODEL.
- Threaded mode:
  - recognition_queue receives latest face sample task.
  - result_queue stores latest recognition result.
  - queue sizes are 1 to avoid backlog and stale latency.

7.4 Matching Logic (app/utils/face_matcher.py)
----------------------------------------------
- Uses cosine similarity (vectorized for performance).
- Chooses top similarity candidate.
- Requires:
  - score >= threshold
  - margin above second-best candidate > margin parameter
- This improves resistance to close false matches.

7.5 Frame Processor (app/services/frame_processor.py)
-----------------------------------------------------
- Maintains current recognized face overlays with TTL.
- Associates detection and recognition by center-distance heuristic.
- Draws labels and confidence on frame.
- Maintains simple frame-level detection cache with TTL and max size.

7.6 Visit Logging (app/services/visit_service.py)
-------------------------------------------------
- Enforces VISIT_COOLDOWN_SECONDS per student.
- Saves screenshot for each logged visit.
- Writes visit row with known status metadata.


================================================================================
8. REGISTRATION WORKFLOWS
================================================================================

8.1 Register from Image File
----------------------------
- Load image from path.
- Detect face(s) using detection service.
- If none found, attempts DeepFace face extraction fallback.
- Uses largest face candidate if multiple faces exist.
- Crops with padding, enhances image, computes embedding.
- Saves enhanced face image to database/faces.
- Adds or updates student entry.

8.2 Register from Multiple Frames
---------------------------------
- Captures multiple samples from guided poses.
- Extracts embedding from each valid sample.
- Averages embeddings and normalizes final vector.
- Saves sample images into per-student folder.
- Adds or updates student row and primary image path.

8.3 GUI Guided Pose Capture
---------------------------
- GUI registration dialog captures an ordered pose script.
- Includes optional glasses captures.
- Requires minimum usable sample count before registration proceeds.

15. PERFORMANCE CHARACTERISTICS AND TUNING GUIDELINES
================================================================================

15.1 Main performance drivers
-----------------------------
- FACE_EMBEDDING_MODEL (Facenet vs larger models)
- PROCESS_INTERVAL_FRAMES
- FRAME_WIDTH / FRAME_HEIGHT
- USE_GPU and actual CUDA availability
- RTSP buffering and network quality

15.2 Throughput vs latency trade-offs
-------------------------------------
- Smaller process interval: fresher recognition, higher compute load.
- Larger process interval: better FPS, slower recognition updates.
- Queue size 1 for recognition minimizes stale decisions.

15.3 Practical tuning sequence
------------------------------
1. Keep DNN detector enabled.
2. Start with 640x480 resolution.
3. Set PROCESS_INTERVAL_FRAMES around 5-10.
4. Validate recognition threshold with real users.
5. Adjust cooldown to control repeated logs.

================================================================================
19. TROUBLESHOOTING PLAYBOOK
================================================================================

19.1 Camera fails to open
-------------------------
- Confirm no other application locks the device.
- Try different CAMERA_INDEX values.
- Validate webcam permission in OS settings.

19.2 RTSP cannot connect
------------------------
- Verify RTSP URL and credentials.
- Confirm source stream is active.
- Test stream with VLC.
- Reduce RTSP buffering and use TCP transport.

19.3 Face not recognized
------------------------
- Re-register student with better lighting and multiple poses.
- Verify FACE_EMBEDDING_MODEL consistency between registration and runtime.
- Tune FACE_RECOGNITION_THRESHOLD in small increments.

19.4 Too many wrong matches
---------------------------
- Lower FACE_RECOGNITION_THRESHOLD for stricter matching.
- Increase DNN_CONFIDENCE_THRESHOLD.
- Increase MIN_FACE_SIZE.

19.5 Low FPS or lag
-------------------
- Lower frame resolution.
- Increase PROCESS_INTERVAL_FRAMES.
- Confirm GPU is actually detected.
- Use smaller embedding model if needed.
