================================================================================
FACE DETECTION SYSTEM - CONFIGURATION GUIDE
================================================================================

This file explains every configuration option in config.py with detailed
meanings, effects on accuracy/performance, and recommended values for
different use cases.

================================================================================
SECTION 1: CORE DETECTION & RECOGNITION SETTINGS
================================================================================

1. CONFIDENCE_THRESHOLD (YOLO)
   Current Default: 0.65
   Range: 0.0 to 1.0
   
   What it does:
   - Controls how confident YOLO must be before reporting a face detection
   - Higher = fewer detections but more accurate
   - Lower = more detections but may include false positives
   
   Recommendations:
   - 0.50-0.60: Very sensitive, good for distant faces, may have false positives
   - 0.65-0.75: Balanced, recommended for most use cases
   - 0.80-0.95: Very strict, only very clear faces
   
   Use case examples:
   - Wide angle camera far from entry: 0.55
   - Camera at entry door (close range): 0.70
   - Security-critical application: 0.80


2. FACE_RECOGNITION_THRESHOLD
   Current Default: 0.35
   Range: 0.0 to 1.0
   
   What it does:
   - Minimum similarity score to consider two faces as matching
   - LOWER value = STRICTER matching (fewer false positives)
   - HIGHER value = MORE LENIENT (may match wrong people)
   
   ⚠️ CRITICAL: This is the MOST IMPORTANT setting for accuracy
   
   Recommendations:
   - 0.25-0.30: Extremely strict (may miss valid matches, very secure)
   - 0.35-0.40: Strict (recommended for high security, good balance)
   - 0.40-0.50: Moderate (good for daily use, rare false matches)
   - 0.50-0.60: Lenient (may have false positives)
   
   Use case examples:
   - Financial transactions: 0.30
   - College canteen logging: 0.40
   - Attendance marking: 0.35
   - General access control: 0.45


3. FACE_EMBEDDING_MODEL
   Current Default: "Facenet"
   Options: "Facenet", "Facenet512", "VGG-Face", "ArcFace", "Dlib", "SFace"
   
   What it does:
   - Selects which AI model extracts face features (embeddings)
   - Different models have different accuracy vs speed tradeoffs
   
   Model comparison:
   
   "Facenet" (128-dimensional)
   - Speed: Fast
   - Accuracy: Good
   - Memory: Low
   - Recommended for: Real-time applications, limited hardware
   
   "Facenet512" (512-dimensional) ⭐ RECOMMENDED FOR BEST ACCURACY
   - Speed: Medium
   - Accuracy: Excellent
   - Memory: Medium
   - Recommended for: Best accuracy without GPU requirement
   
   "VGG-Face" (2622-dimensional)
   - Speed: Slow
   - Accuracy: Very High
   - Memory: High
   - Recommended for: Offline processing, enrollment only
   
   "ArcFace" (512-dimensional)
   - Speed: Medium-Fast
   - Accuracy: Excellent (state-of-the-art)
   - Memory: Medium
   - Recommended for: Modern systems, high accuracy needs
   
   Use case recommendations:
   - Small database (<50 people): Facenet
   - Medium database (50-500): Facenet512 ⭐
   - Large database (500+): ArcFace
   - Offline enrollment: VGG-Face


4. DNN_CONFIDENCE_THRESHOLD
   Current Default: 0.7
   Range: 0.0 to 1.0
   
   What it does:
   - Controls confidence threshold for DNN (Deep Neural Network) face detector
   - Only faces above this score are considered valid detections
   
   Recommendations:
   - 0.40-0.50: Very sensitive, detects partial/distant faces
   - 0.60-0.70: Balanced, good for most scenarios
   - 0.70-0.80: Default, reliable detections
   - 0.80-0.95: Strict, only clear frontal faces
   
   Use case examples:
   - Large room, camera 5+ meters away: 0.50
   - Entry point, 2-3 meters: 0.70
   - Close-up kiosk: 0.80


5. MIN_FACE_SIZE
   Current Default: 60 pixels
   Range: 20 to 200+ pixels
   
   What it does:
   - Minimum width/height of detected face to be considered valid
   - Smaller = detect distant faces (but more noise)
   - Larger = only nearby faces (better quality)
   
   Recommendations by camera distance:
   - 10+ meters away: 30-40 pixels
   - 5-10 meters: 50-60 pixels ⭐
   - 2-5 meters: 60-80 pixels
   - <2 meters (kiosk): 100+ pixels
   
   Camera resolution impact:
   - 320x240 (low res): Use 30-40 pixels
   - 640x480 (medium): Use 50-60 pixels
   - 1280x720 (HD): Use 80-100 pixels
   - 1920x1080 (Full HD): Use 100-150 pixels


6. CASCADE_MIN_NEIGHBORS
   Current Default: 5
   Range: 1 to 10
   
   What it does:
   - Number of neighboring rectangles required for Haar Cascade to accept a detection
   - Higher = fewer false positives, but may miss some real faces
   - Used as fallback when DNN detector is unavailable
   
   Recommendations:
   - 3: Very permissive (many detections, some false positives)
   - 4: Lenient (good for difficult lighting)
   - 5-6: Balanced ⭐ (recommended for most cases)
   - 7-8: Strict (fewer false alarms, may miss some faces)
   - 9+: Very strict (only obvious faces)


================================================================================
SECTION 2: PERFORMANCE & OPTIMIZATION SETTINGS
================================================================================

7. USE_GPU
   Current Default: True
   Options: True / False
   
   What it does:
   - Enables CUDA GPU acceleration for detection and recognition
   - Requires: NVIDIA GPU with CUDA support and proper drivers
   
   Performance impact:
   - CPU only: 3-8 FPS (depending on CPU)
   - With GPU: 15-60 FPS
   
   Recommendations:
   - Set to True if you have NVIDIA GPU (GTX 1050 or better)
   - Set to False if no GPU or AMD/Intel graphics
   - Test both settings to verify GPU is actually being used


8. USE_THREADED_RECOGNITION
   Current Default: True
   Options: True / False
   
   What it does:
   - Runs face recognition in background thread to avoid blocking video
   - Improves responsiveness and frame rate
   
   Impact:
   - True: Smoother video, better FPS, slight recognition delay
   - False: May have frame drops during recognition, lower FPS
   
   Recommendation: Keep True ⭐


9. FRAME_WIDTH & FRAME_HEIGHT
   Current Default: 640x480
   Common options: 320x240, 640x480, 800x600, 1280x720, 1920x1080
   
   What it does:
   - Sets camera capture resolution
   - Higher resolution = better face detail but slower processing
   - Lower resolution = faster but less accurate for distant faces
   
   Resolution guide:
   
   320x240 (QVGA)
   - FPS: Very High (30-60)
   - Accuracy: Low
   - Best for: Testing, very old hardware
   
   640x480 (VGA) ⭐ RECOMMENDED FOR MOST CASES
   - FPS: High (20-30)
   - Accuracy: Good
   - Best for: Real-time with good balance
   
   800x600 (SVGA)
   - FPS: Medium (15-25)
   - Accuracy: Better
   - Best for: Better detail without major slowdown
   
   1280x720 (HD)
   - FPS: Medium (10-20 on CPU, 20-30 on GPU)
   - Accuracy: High
   - Best for: Quality over speed, GPU systems
   
   1920x1080 (Full HD)
   - FPS: Low (5-15 depending on hardware)
   - Accuracy: Very High
   - Best for: Offline processing, powerful GPU


10. PROCESS_INTERVAL_FRAMES
    Current Default: 10
    Range: 1 to 30+
    
    What it does:
    - Process recognition every Nth frame (skip intermediate frames)
    - Lower = more processing, better detection but slower
    - Higher = skip more frames, faster but may miss quick movements
    
    Recommendations by FPS:
    - 30 FPS camera: Use 5-10 (process 3-6 times per second)
    - 15 FPS camera: Use 2-5
    - 10 FPS camera: Use 1-3
    
    Use case recommendations:
    - People walking fast: 3-5 ⭐
    - People stopping at entry: 10-15
    - Slow-moving queue: 15-20
    - Static photo booth: 1


11. USE_DNN_DETECTOR
    Current Default: True
    Options: True / False
    
    What it does:
    - Uses DNN (Deep Neural Network) face detector instead of Haar Cascade
    - DNN is much more accurate but slightly slower
    
    Comparison:
    DNN Detector (True) ⭐ RECOMMENDED
    - Accuracy: Excellent (98%+)
    - Speed: Fast (optimized)
    - Handles angles/lighting: Very well
    
    Haar Cascade (False)
    - Accuracy: Moderate (85-90%)
    - Speed: Slightly faster
    - Handles angles/lighting: Poorly
    
    Recommendation: Always use True unless hardware is extremely limited


12. DETECTION_SCALE
    Current Default: 1.0
    Range: 0.25 to 1.0
    
    What it does:
    - Scales down frame before detection (1.0 = no scaling)
    - Lower = faster detection but less accurate
    
    Recommendations:
    - 1.0: Full resolution, best accuracy ⭐
    - 0.75: Slight speedup, minor quality loss
    - 0.5: 4x faster, noticeable quality loss
    - 0.25: 16x faster, significant quality loss
    
    Use only if CPU is very slow


================================================================================
SECTION 3: TIME & COOLDOWN SETTINGS
================================================================================

13. VISIT_COOLDOWN_SECONDS
    Current Default: 300 (5 minutes)
    Range: 30 to 3600+ seconds
    
    What it does:
    - Prevents logging the same person multiple times within this interval
    - Reduces database spam from people lingering
    
    Recommendations by use case:
    - Canteen entry/exit: 300 seconds (5 min) ⭐
    - Multiple entry points: 600 seconds (10 min)
    - Attendance (morning roll call): 3600 seconds (1 hour)
    - Event check-in: 0 seconds (log every time)
    - Library entry: 1800 seconds (30 min)


14. CURRENT_FACES_TTL_SECONDS
    Current Default: 10 seconds
    Range: 5 to 60 seconds
    
    What it does:
    - How long to display recognition box after face leaves frame
    - Prevents flickering when face temporarily hidden
    
    Recommendations:
    - Fast-moving people: 5-8 seconds
    - Normal walking: 10 seconds ⭐
    - Slow-moving queue: 15-20 seconds


================================================================================
SECTION 4: CAMERA & RTSP SETTINGS
================================================================================

15. CAMERA_INDEX
    Current Default: 0
    Options: 0, 1, 2, etc.
    
    What it does:
    - Selects which camera to use (0 = default/first camera)
    - Change if you have multiple cameras
    
    Finding your camera:
    - Built-in laptop webcam: Usually 0
    - First USB webcam: Usually 0 or 1
    - Second USB webcam: Usually 1 or 2
    
    Tip: If camera doesn't work, try values 0, 1, 2 until you find it


16. USE_RTSP
    Current Default: False
    Options: True / False
    
    What it does:
    - Switches from local camera to network RTSP stream
    - Allows using IP cameras, OBS streams, or remote cameras
    
    When to use RTSP:
    - IP security cameras ✓
    - OBS Studio streaming ✓
    - Remote camera over network ✓
    - Multiple cameras (different RTSP URLs) ✓
    
    When to use local camera:
    - Laptop/USB webcam
    - Simple single-camera setup
    - Testing and development


17. RTSP_BUFFER_SIZE
    Current Default: 100
    Range: 1 to 500
    
    What it does:
    - Number of frames to buffer from RTSP stream
    - Lower = less latency (fresher frames)
    - Higher = smoother playback but delayed
    
    Recommendations:
    - Real-time detection: 1-5 ⭐ (minimal lag)
    - Recording/monitoring: 50-100
    - Unstable network: 100-200


18. RTSP_TRANSPORT
    Current Default: "tcp"
    Options: "tcp" / "udp"
    
    What it does:
    - Network protocol for RTSP streaming
    
    TCP (Recommended) ⭐
    - Reliable: No packet loss
    - Quality: Consistent, no artifacts
    - Latency: Slightly higher
    - Best for: LAN, WiFi, most use cases
    
    UDP
    - Reliable: May lose packets
    - Quality: Can have glitches/artifacts
    - Latency: Lower
    - Best for: Low-latency critical, stable wired network


================================================================================
SECTION 5: ADVANCED TUNING
================================================================================

19. FACE_ENHANCEMENT_TARGET_SIZE
    Current Default: 224 pixels
    Range: 112 to 512 pixels
    
    What it does:
    - Face is resized to this dimension before embedding extraction
    - Larger = potentially better quality but slower
    
    Recommendations:
    - Most models: 224 ⭐
    - High-res enrollment: 256-512
    - Speed critical: 160-224


20. FRAME_CACHE_TTL_SECONDS
    Current Default: 2 seconds
    Range: 1 to 10 seconds
    
    What it does:
    - How long to cache detection results for same frame region
    - Reduces redundant processing for static scenes
    
    Recommendations:
    - Dynamic scene (people moving): 1-2 seconds ⭐
    - Semi-static (queue): 3-5 seconds
    - Static (photo booth): 5-10 seconds


21. RECOGNITION_QUEUE_SIZE
    Current Default: 1
    Range: 1 to 10
    
    What it does:
    - Max number of pending recognition tasks in background thread
    - Size 1 = only process latest frame (recommended)
    - Larger = processes more frames but adds latency
    
    Recommendation: Keep at 1 ⭐

================================================================================
TROUBLESHOOTING GUIDE
================================================================================

PROBLEM: Too many false positive recognitions (wrong people matched)
SOLUTION:
  - Lower FACE_RECOGNITION_THRESHOLD (try 0.35 or 0.30)
  - Increase DNN_CONFIDENCE_THRESHOLD to 0.75-0.80
  - Use Facenet512 instead of Facenet
  - Increase MIN_FACE_SIZE to 70-80

PROBLEM: System not recognizing enrolled students
SOLUTION:
  - Increase FACE_RECOGNITION_THRESHOLD (try 0.45 or 0.50)
  - Lower DNN_CONFIDENCE_THRESHOLD to 0.60-0.65
  - Ensure good lighting during enrollment
  - Re-enroll with multiple angles/expressions
  - Use Facenet512 for better embeddings

PROBLEM: Low frame rate / laggy video
SOLUTION:
  - Reduce FRAME_WIDTH/HEIGHT to 640x480 or 320x240
  - Increase PROCESS_INTERVAL_FRAMES to 15-20
  - Set DETECTION_SCALE to 0.75 or 0.5
  - Ensure USE_GPU is True if you have GPU
  - Use Facenet instead of Facenet512 or VGG-Face

PROBLEM: Not detecting faces at all
SOLUTION:
  - Lower DNN_CONFIDENCE_THRESHOLD to 0.50-0.60
  - Lower MIN_FACE_SIZE to 40-50
  - Ensure USE_DNN_DETECTOR is True
  - Check camera lighting (add lights if dark)
  - Lower CASCADE_MIN_NEIGHBORS to 3-4

PROBLEM: RTSP stream has high latency
SOLUTION:
  - Set RTSP_BUFFER_SIZE to 1-3
  - Use RTSP_TRANSPORT = "tcp"
  - Increase RTSP_PREGRAB_COUNT to 3-5
  - Reduce source FPS in camera settings

PROBLEM: Recognition works but logs spam for same person
SOLUTION:
  - Increase VISIT_COOLDOWN_SECONDS to 600 (10 minutes)
  - Adjust based on your use case needs

PROBLEM: Faces detected but "Unknown" shown for enrolled students
SOLUTION:
  - Increase FACE_RECOGNITION_THRESHOLD slightly
  - Check database has correct face embeddings
  - Re-enroll student with better quality photo
  - Ensure model name matches (Facenet vs Facenet512)
